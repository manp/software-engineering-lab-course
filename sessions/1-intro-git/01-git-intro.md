# 🧾 تاپیک ۱ — آشنایی با گیت و رپازیتوری (Git & Repository)

> «گیت یک سیستم کنترل نسخه‌ی توزیع‌شده است؛ یعنی تاریخچه‌ی کامل پروژه روی ماشین هر کسی که clone می‌کند وجود دارد.»

---

## ۱. گیت (Git) چیست؟

**گیت** یک **سیستم کنترل نسخه (Version Control System)** است که تغییرات فایل‌ها را در طول زمان ثبت می‌کند و به شما اجازه می‌دهد:

- به هر نقطه‌ای از تاریخچه‌ی پروژه برگردید
- بفهمید چه کسی، چه چیزی و چه زمانی تغییر داده است
- چند نفر هم‌زمان روی یک پروژه کار کنند بدون اینکه کار هم را خراب کنند
- شاخه (Branch) بسازید، آزمایش کنید و دوباره ادغام (Merge) کنید

### چرا به گیت نیاز داریم؟

| مشکل بدون گیت | راه‌حل با گیت |
|---|---|
| فایل‌های `final_v2_ok.zip` و نسخه‌های تکراری | تاریخچه‌ی منظم با commit های قابل توضیح |
| ترس از خراب شدن پروژه | بازگشت آسان به آخرین نسخه‌ی سالم |
| هم‌کاری چندنفره‌ی پرخطا | merge و مدیریت تعارض (Conflict) |
| از بین رفتن کار با خرابی لپ‌تاپ | مخزن روی GitHub هم به‌عنوان پشتیبان |

---

## ۲. رپازیتوری (Repository) چیست؟

**رپازیتوری (مخزن)** یعنی همان پوشه‌ی پروژه‌ی تو به‌همراه تاریخچه‌ی کامل تغییراتش. گیت اطلاعاتش را در پوشه‌ی مخفی `.git/` داخل همان پروژه نگه می‌دارد.

انواع رپازیتوری:

- **Local (محلی):** روی سیستم خودت — `git init`
- **Remote (راه دور):** روی سرویسی مثل GitHub — `git remote add ...`

سه ناحیه‌ی مهم در گیت:

```mermaid
flowchart LR
    W[Working Directory<br/>فایل‌هایی که ویرایش می‌کنی] -->|git add| S[Staging Area<br/>آماده‌سازی تغییرات]
    S -->|git commit| R[Repository<br/>ثبت در تاریخچه]
```

## ۳. نصب و تنظیم اولیه

### نصب روی لینوکس (Ubuntu/Debian)
```bash
sudo apt update && sudo apt install -y git
```

### نصب روی ویندوز
- دانلود از https://git-scm.com/download/win و نصب با تنظیمات پیش‌فرض
- بعد از نصب، از **Git Bash** استفاده کنید

### نصب روی macOS
```bash
brew install git
```

### تنظیم هویت (یک‌بار برای همیشه)
```bash
git config --global user.name "Your Name"
git config --global user.email "your-email@example.com"
```
> ایمیل باید همان ایمیلی باشد که در GitHub ثبت می‌کنید تا commit هایتان به حساب‌تان وصل شود.

## ۴. دستورهای پایه‌ی گیت

| دستور | کار |
|---|---|
| `git init` | ساختن رپازیتوری جدید در پوشه‌ی فعلی |
| `git status` | نمایش وضعیت فایل‌ها (تغییر داده‌شده، آماده، ثبت‌نشده) |
| `git add <file>` | افزودن فایل به Staging Area |
| `git add .` | افزودن همه‌ی تغییرات به Staging Area |
| `git commit -m "message"` | ثبت تغییرات با یک پیام توضیحی |
| `git log --oneline` | مشاهده‌ی تاریخچه‌ی commit ها |
| `git diff` | دیدن تغییرات فایل‌ها قبل از commit |
| `git branch` | لیست شاخه‌ها |
| `git remote -v` | نمایش آدرس مخازن راه دور متصل |
| `git push` | ارسال commit ها به مخزن راه دور |
| `git pull` | دریافت آخرین تغییرات از مخزن راه دور |

### اولین چرخه‌ی کاری
```bash
# داخل پوشه‌ی پروژه
 git init
git add .
git commit -m "اولین commit"
```

### پیام commit خوب چه ویژگی‌هایی دارد؟
- کوتاه و توصیفی باشد (حداکثر ~۷۰ حرف)
- با فعل امر شروع شود: fix، add، update، remove
- مثال: `add: فایل README پروژه اضافه شد`
- مثال بد: `changes` یا `aaaa`

## ۵. تمرین کوتاه

1. یک پوشه به نام `git-practice` بسازید و وارد آن شوید.
2. `git init` بزنید.
3. یک فایل `hello.txt` با متن دلخواه بسازید.
4. `git status` بزنید و خروجی را ببینید.
5. `git add hello.txt` سپس `git commit -m "add: فایل hello اضافه شد"` بزنید.
6. `git log --oneline` بزنید — اولین commit شما ثبت شده است.
